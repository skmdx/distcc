distcc protocols 6 through 11: LZ4 compression and HTTP/2
======================================================

Protocol 6 follows protocol 2 (client preprocessing), and protocol 7 follows
protocol 3 (server preprocessing). All compressed bulk payloads use LZ4
instead of LZO. Metadata, arguments, file names and symlinks are unchanged.
DONE echoes the request's version. Both versions work inside protocol 5
sessions and worker admission; protocol 4 link jobs remain unchanged.

The host option is ,lz4, combined with ,cpp for protocol 7. There is no
automatic codec negotiation: upgrade the server before enabling this option.
Protocols 1 through 5 and the ,lzo option retain their existing wire format.

Each nonempty bulk payload consists of a four-byte unsigned uncompressed
length in network byte order followed by one raw LZ4 block. The enclosing
token's length includes this prefix. Compression uses LZ4_compress_default;
decoding uses LZ4_decompress_safe and must produce exactly the declared length.
Lengths above LZ4_MAX_INPUT_SIZE, compressed lengths above compressBound for
the declared size, malformed blocks and truncated input are rejected.
Empty files may use a zero token length or a valid block with declared size 0.

The local include-server request retains CDIR followed by the argument vector.
LZ4 requests replace its ARGC token with LZ4C; argument strings still use ARGV.
An ARGC request selects LZO, preserving existing include-server clients.
Responses retain ARGC/ARGV file lists. Compressed cache files use .lz4 or
.lzo plus optional .abs, so one include server can serve either codec without
recompressing cached headers. New clients must restart old include servers;
unsupported requests fail include analysis rather than mislabeling LZO data.

Chunked payloads (8, 9 and 10)
-----------------------------

Protocol 8 follows 6, protocol 9 follows 7, and protocol 10 follows the
protocol 4 link exchange. All bulk payloads use independent LZ4 chunks. The
host option is ,lz4s (or ,h2); there is no automatic codec downgrade.

An empty payload has token length zero. Otherwise the token length is
0xffffffff, followed by pairs of uint32 values in network byte order:
uncompressed length and encoded length. The uncompressed length is between
1 and 262144. Encoded length zero denotes raw bytes; a nonzero encoded length
must be smaller than the uncompressed length and denotes a raw LZ4 block.
Exactly that many encoded (or raw) bytes follow each pair. A pair of zeros
ends the payload. Invalid lengths, truncated input and decompression sizes
that differ from the declared size are rejected. No total compressed length
or complete-payload allocation is required. Result files retain the usual
temporary-file and publication rules.

The include-server token LZ4S selects .lz4s cache files. These contain the
chunk pairs, data and terminator, without the outer RPC token. The caches
remain separate from .lz4 and .lzo files.

The C sender sizes its buffers to the file or chunk, whichever is smaller,
and sends raw chunks from the input buffer without copying their contents.
The receiver allocates buffers as chunks arrive and decodes diagnostics
directly into the retained result buffer. Diagnostic publication and result
file cleanup retain their existing semantics.

HTTP/2 transport
----------------

The broker opens a prior-knowledge cleartext HTTP/2 connection on the existing
distccd port. The prefork parent checks the existing IP ACL before accepting
the session. There is no HTTP/1 upgrade, TLS, SSH or GSSAPI wrapper.
Each job is POST /v1/compile or POST /v1/link, with one RPC exchange in its
DATA frames. Response status 200 grants a worker; 503 refuses without starting
execution, allowing another host to be selected. A connection failure after
admission retains the existing failed-job policy; it is not a safe refusal.

The broker and prefork parent own HTTP/2 framing. Jobs use private local
sockets, preserving existing compiler and link-helper I/O. A request's
END_STREAM does not disconnect the worker's local input while it compiles;
RST_STREAM or loss of the connection cancels it. Response END_STREAM signals
local EOF after queued result bytes drain. Lease cancellation is scoped to
both the connection generation and stream ID.

Receive windows are 256 KiB per stream and 8 MiB per connection. WINDOW_UPDATE
is issued when the local consumer drains data. A writable local consumer
receives DATA directly; a 256 KiB queue is allocated only when it falls behind.
The sender stops polling local producers while HTTP/2 or network output is
blocked. Large serialized frames remain in nghttp2's buffer through partial
writes; up to 4 KiB of small frames are coalesced and sent alongside them.

Connections advertise a 64 KiB maximum frame and at most 256 concurrent
streams. DATA reads respect the peer's frame limit and both flow-control
windows, including older peers using 16 KiB frames. Worker/resource admission
still determines executable concurrency. Idle server connections expire after
30 s. The admission exchange is unchanged. Objects and link inputs are not
cached between jobs; source inputs can use protocol 11 as described below.

Cached input manifests (11)
--------------------------

An HTTP/2 response advertises x-distcc-cache: 1 when the daemon supports
cached inputs. The broker conveys this capability with its job descriptor.
For server preprocessing, clients with include-server SHA-256 sidecars use
protocol 11 when an all-hit manifest would save at least 16 KiB, estimated
from compressed file sizes minus digest sizes. Smaller jobs, clients without
digests and peers without this header retain protocol 9. This avoids the
missing-set round trip for small inputs. Old clients ignore the additional
HTTP header. Protocol 11 has
the same command, working-directory and result exchange as protocol 9.

NFIL is followed by a complete input manifest. Each entry has NAME and
either HASH (length 32, raw SHA-256 of the uncompressed contents including
any inserted #line directive), LINK, or FILE with length zero for a directory
placeholder. Names are unique absolute paths without dot or empty components;
the manifest is limited to 65536 entries and paths shorter than MAXPATHLEN.
The server materializes verified cache hits into private job files, then
sends MISS with length NFIL and one byte per entry (1 = upload, 0 = present).
Only HASH entries can require upload. The client sends FILE payloads for the
missing entries in manifest order, using the existing chunked LZ4 encoding.
There is one missing-set round trip per job, not one per file. A digest
mismatch aborts the job before execution. Request END_STREAM follows uploads.

The include server hashes contents while producing its immutable compressed
snapshot and stores the raw digest in a .sha256 sidecar. Existing mutation
checks invalidate the compressed snapshot and digest together. Cache hits
are copied or reflinked, verified, and owned by the job; eviction cannot
invalidate an active input. Uploads are verified before atomic publication,
and cache insertion never waits for another uploader's lock.

DISTCCD_FILE_CACHE chooses a private daemon-owned directory. By default it is
distcc-cache-<uid> under the daemon's TMPDIR. An explicitly empty value disables
the capability. The cache is sharded into 64 directories, each limited to
64 files and 4 MiB, for at most 4096 files and 256 MiB of payload. Shards evict
oldest entries on insertion; files larger than 4 MiB are transferred but not
retained. Cache storage failures become misses or skipped insertions and do
not invalidate verified job inputs. Keep this directory on tmpfs when memory
permits, or on storage with reflink support to reduce snapshot writes.
