distcc protocols 6 through 10 and prepared jobs
=============================================

Protocol 6 follows protocol 2 (client preprocessing), and protocol 7 follows
protocol 3 (server preprocessing). All compressed bulk payloads use LZ4
instead of LZO. Metadata, arguments, file names and symlinks are unchanged.
DONE echoes the request's version. Both versions work inside protocol 5
sessions and worker admission; protocol 4 link jobs remain unchanged.

The host option is ,lz4, combined with ,cpp for protocol 7. There is no
automatic codec negotiation: upgrade the server before enabling this option.
Protocols 1 through 5 and the ,lzo option retain their existing wire format.

Each nonempty bulk payload consists of a four-byte unsigned uncompressed
length in network byte order followed by one raw LZ4 block. The enclosing
token's length includes this prefix. Compression uses LZ4_compress_default;
decoding uses LZ4_decompress_safe and must produce exactly the declared length.
Lengths above LZ4_MAX_INPUT_SIZE, compressed lengths above compressBound for
the declared size, malformed blocks and truncated input are rejected.
Empty files may use a zero token length or a valid block with declared size 0.

The local include-server request retains CDIR followed by the argument vector.
LZ4 requests replace its ARGC token with LZ4C; argument strings still use ARGV.
An ARGC request selects LZO, preserving existing include-server clients.
Responses retain ARGC/ARGV file lists. Compressed cache files use .lz4 or
.lzo plus optional .abs, so one include server can serve either codec without
recompressing cached headers. New clients must restart old include servers;
unsupported requests fail include analysis rather than mislabeling LZO data.

Chunked payloads (8, 9 and 10)
-----------------------------

Protocol 8 follows 6, protocol 9 follows 7, and protocol 10 follows the
protocol 4 link exchange. All bulk payloads use independent LZ4 chunks. The
host option is ,lz4s; there is no automatic codec downgrade.

An empty payload has token length zero. Otherwise the token length is
0xffffffff, followed by pairs of uint32 values in network byte order:
uncompressed length and encoded length. The uncompressed length is between
1 and 262144. Encoded length zero denotes raw bytes; a nonzero encoded length
must be smaller than the uncompressed length and denotes a raw LZ4 block.
Exactly that many encoded (or raw) bytes follow each pair. A pair of zeros
ends the payload. Invalid lengths, truncated input and decompression sizes
that differ from the declared size are rejected. No total compressed length
or complete-payload allocation is required. Result files retain the usual
temporary-file and publication rules.

The include-server token LZ4S selects .lz4s cache files. These contain the
chunk pairs, data and terminator, without the outer RPC token. The caches
remain separate from .lz4 and .lzo files.

The C sender sizes its buffers to the file or chunk, whichever is smaller,
and sends raw chunks from the input buffer without copying their contents.
The receiver allocates buffers as chunks arrive and decodes diagnostics
directly into the retained result buffer. Diagnostic publication and result
file cleanup retain their existing semantics.

Pooled TCP jobs
--------------

The new TCP job protocol keeps one outstanding job per reusable connection.
The client broker loans the connected socket; it never relays file bodies.
The distccd parent owns sockets, input trees, cache upload owners and the ready
queue in one nonblocking event loop. Existing persistent compiler workers only
execute prepared jobs. Receiving and returning results do not occupy execution
slots. A worker receives RUN with a metadata FD and private root, and returns
FINISHED with status and all result FDs in one SOCK_SEQPACKET message. Successful
FD transfer releases the sender's references. No per-file IPC or idle ACK is
needed. Results and availability are committed together after worker cleanup.

A job has three phases: preparing, running, returning. Readiness follows from
the remaining input count; completion destroys the job and leaves an idle
connection. Only the parent changes queue membership and cache ownership.
Missing cached inputs have one uploader and a list of dependants. Publication
wakes dependants; disconnect promotes another uploader. Inputs are private
snapshots, never compiler-writable cache inodes. No inter-job upload locks are
held while waiting for a compiler or another input. Preparation advances at
most eight input entries per turn and stops after each cache hit. Completed
shared uploads copy one dependant per turn without rehashing the verified
source; that source cannot enter a compiler until all copies finish. Cache
hits from persistent storage still undergo verification.

The network exchange is BEGIN(manifest), NEED(missing cached input indices), input
chunks, RESULT(status and artifact sizes), output chunks, COMPLETE(job id).
Uncached inputs start immediately after BEGIN, without waiting for NEED.
Further NEED messages can promote a cache waiter after an uploader disconnects.
Both endpoints continue to service control traffic during transfers. There is
no per-file ACK, artifact GET or job DELETE. Every frame has a type/flags word
and payload length in network byte order. Data chunks use raw bytes or an
independent LZ4 block; expanded size and final markers are checked. Existing
pump snapshots are translated chunk by chunk without whole-file expansion.
Live compression uses bounded buffers, not a fully compressed staging memfd.
RAW and already encoded immutable file extents can use sendfile.

The host option is ,tcp (or ,cpp,tcp under pump). It requires the Linux broker
and prefork daemon, uses the existing ACL-protected TCP listener, and does not
support SSH or GSSAPI. BEGIN is type 0x54000200, followed
by NEED, INPUT, RESULT, OUTPUT and COMPLETE in numeric order. The eight-byte
frame header contains a uint32 type/flags and uint32 payload length. Flag
0x10000 means compressed; 0x20000 means final, both valid only on data frames.
All integers use network byte order. Payloads are:

  BEGIN:    uint64 nonzero job ID, then the binary manifest described below.
  NEED:     a nonempty vector of uint32 cached input indices.
  INPUT:    uint32 index, uint32 expanded chunk length, raw/LZ4 bytes.
  RESULT:   uint32 wait status, uint32 mode, four uint64 expanded sizes.
  OUTPUT:   the same chunk structure as INPUT, indexed by artifact.
  COMPLETE: uint64 job ID matching BEGIN.

Data chunks expand to at most 256 KiB. A compressed chunk must be smaller than
its expanded size. Zero-length inputs have an explicit final chunk; zero-length
outputs have no chunks. Every nonempty input/output must reach its declared
size with a final marker. Manifest encoding describes the source snapshot;
each data frame independently describes its wire encoding.

Admission bounds connections (256) and globally retained input estimates,
output sizes, frame buffers and queued packets (512 MiB) independently of
compiler slots. These bounds exclude compiler working memory and the separate
256 MiB persistent cache. Each connection has one 256 KiB working buffer.
Compressed inputs and output chunks of at least 64 KiB use a lazy pool of at
most two threads (one on a single-CPU host). A connection has at most one task;
the event loop retains its frame, file descriptors and storage reservation
until task completion. The threads expand/write/hash input or read/compress
output; only the event loop changes job/cache/queue ownership. Small chunks
and raw inputs stay synchronous. Raw receive frames are written directly;
raw result sendfile extents need no intermediate payload copy. Temporary
output encoding buffers count against the storage budget.
All transfer threads are joined before compiler-worker fork or daemon cleanup;
they restart lazily. Cancelled jobs retain task resources until completion.
At most four frames or writes per connection per turn prevent large transfers
from monopolizing the event loop. Retained output pauses dispatch above three
quarters of the storage budget. Ready jobs dispatch FIFO; ordinary compiles
may pass a link blocked by the one-link-per-server limit.
Cancellation closes the connection; a running worker is cancelled and reaped
before its input tree is removed. Prepared workers and compiler descendants
share a process group, so worker death also terminates its compiler. Compiler
temporaries use the private input root. Normal daemon shutdown cancels and
reaps workers before deleting roots. Input roots are reclaimed at FINISHED;
result FDs survive independently until transfer completes. Only validated COMPLETE permits client
publication and pool return. Partial or malformed transactions are discarded,
never resynchronized or silently replayed. Idle sockets own no compiler slot.
Idle connections expire after 30 seconds; jobs use DISTCC_IO_TIMEOUT measured
from network progress or worker completion. Receiving clients stage decoded
artifacts until COMPLETE. Object/dependency chunks decode directly into a
private temporary file beside the destination; COMPLETE permits rename, with
no memfd-to-file copy. Diagnostics retain anonymous storage. The connection
returns to the pool before local publication; a publication error cannot make
an incomplete network transaction reusable and does not blacklist or retry a
healthy server. The version-1 prepared TCP wire
format is rejected; update clients and daemons together.

The stats counter dcc_tcp_ready_idle_ns accumulates unused admissible compiler
slot nanoseconds while eligible prepared work is queued. It is sampled at
queue/worker transitions, and includes result processing or output backpressure
that delays dispatch; input waiting and unavailable resource slots are excluded.
The dcc_tcp_parallel_tasks and dcc_tcp_parallel_peak counters report completed
background chunks and the peak number of concurrently executing chunk tasks.
Use bench/rpc.py to compare actual builds with fallback and retries disabled.

Job manifest
------------

Manifest scalars are unsigned 64-bit integers in network byte order. Strings
are a length scalar followed by bytes, without NUL. Fields are: job kind
(0 compile, 1 pump, 2 link), argc, input count, cwd, argv strings, then inputs.
Each input carries kind (0 file, 1 symlink, 2 empty placeholder), encoding
(0 raw, 1 LZ4 chunks), cached flag, wire size, expanded size, eight raw XXH3-64
digest bytes, absolute path and link target strings. Count and argc are at
most 65536; metadata is at most 16 MiB. Paths have no empty/dot components.

Input cache
-----------

Pump snapshots include a .xxh3 sidecar containing the default-seed XXH3-64
digest followed by the expanded uint64 length (16 bytes, network byte order).
Mutation checks invalidate the snapshot and sidecar together. If a sidecar is
missing, the client does not use that manifest for cache lookup; it can recover
expanded lengths from LZ4 chunk headers without decompression.

The client uses cache keys when expected all-hit savings reach 16 KiB.
Files larger than 4 MiB are never cached. Every job still uses its transport's
manifest/input exchange; small inputs do not use a legacy fast-path RPC.
Hits are copied or reflinked into private job files and verified. On systems
without reflink, verification happens during copying. Duplicate contents
share one upload but have independent snapshots. Pooled TCP keeps upload
owners and waiters in the server event loop; it does not require client-side
inter-job leases.

XXH3-64 detects accidental changes; it is not collision resistant against
adversarial input. Upload verification precedes atomic cache publication.
DISTCCD_FILE_CACHE selects a private daemon-owned directory, defaulting to
distcc-cache-<uid> under TMPDIR. An empty value disables retention; jobs then
upload every required file. The cache has 64 shards, each limited to 64 files
and 4 MiB, for at most 4096 files and 256 MiB. Insertion locks are nonblocking;
eviction or storage failure can cause later reuploads without invalidating
private inputs. Prefer tmpfs when memory permits or reflink-capable storage.
