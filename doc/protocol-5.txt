distcc sequential TCP sessions
=============================

Before sending any job, a client may send DIST00000005 on a fresh TCP
connection. A supporting server replies POOL00000001 and retains the
connection. POOL00000000 or a closed/rejected connection means that the
client must reconnect and use the original single-job protocol. No job has
been submitted at this point, so this negotiation fallback cannot duplicate
compilation or linking. GSSAPI and SSH connections do not negotiate sessions.

After successful negotiation, each request uses protocol 1, 2, 3, 4, 6 or 7,
starting with its own DIST token. The corresponding response
retains its original DONE version and payload. After all response bytes and
job cleanup, the server sends JEND00000000. This boundary also follows a
complete response reporting a compiler/linker error. Protocol errors, partial
transfers and aborted jobs close the connection without promising reuse.

The client must consume JEND before returning the connection to its broker.
There is at most one outstanding job per connection; requests are not
multiplexed or pipelined. Each new job obtains a fresh scheduling reservation.
The server may close an idle session at any time. Clients discard known stale
idle sockets before use; a failure after job transmission follows ordinary
distcc error/fallback handling, not an automatic pool-level resend.

The Linux preforking parent owns idle sessions and assigns sockets to workers
only when another request becomes readable. An idle session consumes a socket,
not a compiler worker. Both broker and server bound retained socket counts
and idle lifetimes. Clients without negotiation receive no JEND and retain
the original single-job behavior.

Worker admission
----------------

A Linux server advertising dcc_admission 1 in its statistics also accepts
SLOT00000001 (compile) or SLOT00000002 (link) on a fresh or idle pooled TCP
connection. These requests use the ordinary server access rules and are not
available with GSSAPI. They carry no compiler arguments or input files.

GRNT00000001 atomically reserves a worker and enables the same sequential
session framing described above. Send one ordinary DIST request next and
consume its complete response, including JEND, before reusing the connection.
Closing an abandoned connection releases the reservation through the worker's
normal EOF/error path. Existing I/O and job lifetime limits still apply.

BUSY00000000 reserves nothing and leaves the connection idle. The broker may
try another host; it waits at least 50ms before retrying this host for the same
job class. A link needs a free worker, no other admitted link on this server,
and memory PSI below 10% when available. Ordinary compile admission needs a
free worker. Legacy requests remain supported without a SLOT exchange.
